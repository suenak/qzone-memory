# 媒体与账号数据补齐

本次对照 xiaosu19 上游 `cabd5b1` 和 zhang-sen-sen 派生版 `7eecd85`，补齐媒体和账号管理。保留现有多平台发行方式，没有增加 Windows 便携版、Linux 或 NixOS 包。

## 使用方式

- 相册中的视频会显示「播放视频」，在客户端内播放。播放地址返回 HTTP 403 时，每 60 秒最多自动刷新一次视频列表并重试；网络错误、授权错误不会触发刷新。
- 旧相册视频优先按明确视频 ID、唯一封面标识或唯一的同名同时间记录关联。无法确认时，点击「选择对应视频」，选择本账号已保存的视频，关联会留在当前账号数据库里。不采用仅凭列表顺序的自动关联。
- 相册照片打开时优先读取原图并保存到本机；说说照片采用同一套原图候选策略。原图不可用时尝试接口保留的其他地址，不能保证所有旧照片仍有原图。
- 说说、说说媒体、相册共用图片查看器：滚轮／按钮／双指缩放、拖动、旋转、复位、左右切换、长按保存、键盘操作与焦点恢复。
- 新下载的媒体使用本地时间 `年-月-日_时-分-秒_内容哈希.扩展名` 命名。时间缺失时明确使用「时间未知」。另存图片默认文件名也带记录时间。
- 图片和视频分别建立缓存索引。相同地址可以直接复用；同一 PSC 原图跨域地址可复用；地址或签名不同的内容下载后按 SHA-256 合并，避免长期保存重复文件。没有可靠对应关系的两个 URL 必须先取得内容才能判断是否相同。

## 数据目录与迁移

数据继续放在系统应用数据目录，账号之间分开：

```text
应用数据目录/
  accounts/
    qq_账号/
      qzone-archive.sqlite3
      images/                 # 包含图片和媒体索引
      videos/                 # 包含视频和媒体索引
  last-account.txt            # 仅记录 QQ 号，不记录登录凭据
  qzone-archive.sqlite3       # 旧版迁移备份，保留不改写
```

第一次访问旧账号时，使用 SQLite `VACUUM INTO` 取得包含已提交 WAL 数据的一致性快照，再过滤其他账号的记录，保留原记录 ID。完成后才把临时库更名为账号数据库；失败可以重试。旧图片与视频保留原文件作为迁移备份，新目录复制完成后记录标记。旧缓存名保留兼容读取；新下载文件使用时间命名。

设置中的「查看本机其他账号」列出已迁移账号及旧库中的账号。退出 QQ 登录后可以切换本地账号，离线查看、搜索和导出。登录后的写入仍严格限定当前 QQ 账号。

「删除当前账号数据」只清理当前账号目录和 QQ 登录状态，保留其他账号和软件授权。删除标记会阻止旧备份自动再次导入。旧版迁移备份与另存的导出文件需要用户自行删除。

登录 Cookie 仍只保存在系统凭据库；本次没有把凭据移到账号目录。

## 验证边界

- Rust 单元测试覆盖迁移后账号隔离、原记录 ID、旧库保留、媒体去重、截断缓存失效、视频识别、跨账号关联阻止和匹配歧义。
- 浏览器挂载真实组件，使用明确标记的合成记录与合成媒体验证 UI：320／390／800／1440 像素、明暗主题、旋转缩放切图、焦点恢复、错误重试、视频解码、403 刷新一次、手动关联、网络错误不刷新。
- UI 验证不等于 QQ 生产接口或 Android／iOS／macOS 实机验证。没有修改真实用户数据库或调用真实 QQ 账号完成业务测试；原生保存对话框未在浏览器验证。
- 采用 orchestrate-frontend-design 与 frontend-design；本机没有 design-cross-platform-ui skill，按已安装流程与项目规范继续。

## 代码入口

- `src-tauri/src/account_storage.rs`：账号目录、旧库迁移、本地账号选择。
- `src-tauri/src/media_store.rs`：原图候选、有界下载、完整性校验、内容去重和时间命名。
- `src-tauri/src/archive.rs`：媒体命令、相册视频关联、导出和当前账号删除。
- `src/components/ImageViewer.vue`：共用图片查看器。

媒体功能对照来源：[zhang-sen-sen/QQ-Zone-Restore-Archive](https://github.com/zhang-sen-sen/QQ-Zone-Restore-Archive)。恢复条件及基础数据通道保持本项目原有约定。
