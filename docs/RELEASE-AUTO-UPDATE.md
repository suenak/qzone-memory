# 客户端更新与发布

客户端在启动时自动检查新版本；保持运行且页面可见时，每 6 小时再检查一次。返回应用时若距上次检查已超过 6 小时，也会检查。设置 → 关于 → 应用更新提供手动检查。

默认流程：展示版本和更新内容 → 点击「下载安装包」 → 在客户端查看下载进度 → 点击「打开安装包」 → 按系统提示安装。设置中的「自动下载安装包」默认关闭，用户可自行开启。下载不会自动安装。

## 平台与操作

- Windows x64 下载 EXE / MSI，完成后可打开安装包或所在文件夹。
- macOS 根据编译架构选择 Apple 芯片或 Intel DMG，打开后按系统方式安装。
- Android 下载 APK。打开时检查包名，仅向系统安装器签发更新缓存目录的 FileProvider URI。首次需要允许拾忆安装应用；允许后返回客户端，再点「打开安装包」。系统继续检查签名与安装兼容性。
- iOS 使用备用下载页，不能通过下载 IPA 在应用内替换安装；Linux 当前没有发布安装包。
- 恢复或资料同步任务运行期间可以下载，打开安装包前须停止任务。后端也检查该条件。
- 「后台下载」仅关闭更新窗口，下载继续；关于页的「查看下载」可以重新打开。取消和失败会清理 `.part` 文件，支持重试。下载不支持跨进程断点续传。
- 自动检查失败不打扰用户，手动检查显示失败原因。有新版时同一会话内不会反复提醒用户已关闭的同一版本。

## 清单

固定地址 `GET <更新服务>/api/v1/update/latest`，没有可用新版本返回 204。旧客户端仍能读取新清单。

```json
{
  "version": "1.2.7",
  "notes": "更新说明，支持换行",
  "pub_date": "2026-10-13T00:00:00Z",
  "download_page": "https://example.com/",
  "platforms": {
    "windows-x86_64": {
      "url": "https://example.com/api/v1/update/download/qzone-memory_1.2.7_x64-setup.exe",
      "file_name": "qzone-memory_1.2.7_x64-setup.exe",
      "size": 20971520,
      "sha256": "64位十六进制SHA256"
    }
  }
}
```

下载命令只接受期望版本号，不接受前端指定 URL、保存路径或凭据。Rust 重新读取配置的清单，确认版本没有撤回或变更，选择当前编译平台的安装包。Windows 不会下载 Android 包。版本比较仅支持三段数字版本，不把预发布后缀当正式更新。

清单超时 10 秒，上限 512 KiB。安装包上限 512 MiB；连接超时 10 秒，连续 30 秒无数据就失败，整个下载最多 30 分钟。安装包保存到应用缓存的 `update-packages/<version>/`。

生产下载只接受 HTTPS；重定向最多 5 次，每次检查安全协议、拒绝 URL 内的凭据。仅本地开发的 loopback HTTP 清单允许同源 HTTP 下载。请求使用独立网络客户端，不携带 QQ Cookie、授权凭据或应用账号信息。

新服务端异步读取文件生成 SHA-256，并按路径、大小和文件修改时间缓存；不会改变数据库结构，因此不会因本改动提高蓝绿切换的 schema 版本。新客户端检查文件大小、摘要和安装包类型；打开安装包前再次核对下载时记录的摘要。旧 HTTPS 清单没有摘要时仍可下载，依赖 TLS、响应长度和安装包类型检查，不能声称具备清单摘要校验。SHA-256 是传输及文件一致性检查，不能代替发布者签名；没有恢复 minisign 自安装流程。

## 配置与发布

配置仍从构建期环境变量、`src-tauri/qza.config.local.json`、`src-tauri/qza.config.json` 依次读取。真实本地配置不入库：

```json
{
  "QZA_UPDATE_ENDPOINT": "https://example.com/api/v1/update/latest",
  "QZA_DOWNLOAD_PAGE": "https://example.com/"
}
```

服务端设置 `QZA_PUBLIC_URL` 和 `QZA_DOWNLOAD_PAGE`，以保证反代后清单返回可访问地址。

发布流程：

1. 构建平台安装包，确保配置正确。Windows 使用 `npm run tauri:build:windows`；Android Release 仅包含 ARM / ARM64。
2. 管理后台「客户端版本」填版本及说明，上传对应平台安装包，发布。
3. 检查清单包含正确版本、平台地址、大小和摘要；下载实际文件核对 SHA-256。
4. 用旧版本客户端确认检查、下载、打开安装包和覆盖安装；现有本地记录必须保留。

无需 minisign 密钥；Android 和 macOS 的系统安装要求仍适用。撤销发布后清单返回 204，尚未开始下载的客户端会重新读取清单并拒绝已撤回版本。已完成的本地下载不会被自动删除。

## 验证记录

2026-10-13 的本地改动：86 项 Rust 测试、151 项服务端端到端检查通过；前端构建、Windows Rust 检查、Android x86_64 开发目标 Rust 检查、Android Universal Debug Kotlin 编译与 manifest 合并通过。

Rust 使用真实本地 HTTP 传输验证正常下载、摘要不一致、连接中断、取消清理、无凭据请求、平台选择及打开前文件变更。浏览器以模拟 IPC 验证自动检查时默认不下载、下载、取消、重试、后台下载、完成提示和打开命令，检查 390 与 1440 像素布局及深色错误状态。另验证检查失败提示、缺平台包时隐藏下载按钮，以及任务忙碌时禁止打开安装包。浏览器模拟不能替代原生安装，也未在真实 macOS、iOS 或 Android 物理设备上验收。

UI 沿用现有语义 token 和组件，按 `orchestrate-frontend-design` 简化流程执行；辅助技能 `design-cross-platform-ui` 未安装，采用现有跨平台规范与原生编译检查。

本次修改不等于线上部署或正式客户端发布。旧客户端需要先安装包含此功能的新版，才具备应用内下载入口。
