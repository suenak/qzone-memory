# Windows 安装升级修复

## 本机观察

用户截图显示旧版安装器在“安装前卸载”时提示“无法卸载”。本次检查时正在运行的是之前 `media-fix-1.2.8` 目录内的 `qzone-memory_1.2.8_x64-setup.exe`。

首次检查时系统安装记录仍为 1.2.7；旧程序和卸载器均存在，路径记录也指向现有目录。只做了 Windows 挂起创建检测：卸载器可由系统加载，并在入口执行前终止，没有实际运行卸载逻辑。

用户随后遇到“无法打开要写入的文件 qzonearchive.exe”。进一步检查确认工作区输出目录带有继承的 Low 强制完整性标签。这里的安装包启动后进程完整性 RID 为 4096，无法正常写入中完整性的安装目录及常规安装注册表项。上次仅将问题归为旧卸载流程和受限测试环境，诊断不完整；不能靠跳过卸载彻底解决。

## 修复

`src-tauri/nsis-installer.nsi` 在识别同一 NSIS 应用的同版本重装或新版本升级时，跳过维护页并继续正常安装：

- 不再先调用旧卸载器，避免升级依赖旧版本的卸载逻辑，也不触发旧卸载器的数据删除问题。
- 继续执行程序占用检查、文件写入、卸载器生成及安装记录更新。
- 继续读取原安装目录，应用标识与安装识别键不变。
- MSI 迁移及禁止降级的检查保留原流程。

此修复不修改旧版卸载程序，也未直接替换用户已安装的客户端。

`scripts/export-windows-installer.ps1` 增加本地交付步骤：

- 将安装包复制为正常用户目录中的新文件，默认位置为系统下载目录的“拾忆安装包”文件夹。
- 校验导出前后 SHA-256 相同，并读取 NTFS 强制完整性标签；如果目标目录或文件仍带 Low / Untrusted 标签，则拒绝交付。
- 不修改安装目录或系统注册表的权限，不手动提升进程权限，不改动安装包内容。
- `build-local-windows.ps1` 在交付本地构建时调用导出步骤；开发工作区中的构建产物不再直接作为本地安装下载链接。

## 验证

- `npx tauri bundle --bundles nsis` 成功。
- 从实际生成的 NSIS 脚本创建隔离测试副本，仅替换测试名称、程序文件名、注册表位置和输出目录，添加升级分支记录；使用实际生产程序作为文件载荷。
- 三种原生安装流程全部通过：旧卸载器明确返回错误、旧卸载器不存在、同版本重装。每次均确认进入覆盖安装分支、旧卸载器未被执行、新程序替换成功、版本记录更新到 1.2.8、目录内数据标记保留。
- 早期测试只在 AppDataLow 临时注册表位置通过，未能证明安装包能够正常安装。修正交付方式后，从下载目录运行隔离安装器，在普通 HKCU 安装项命名空间重测三种流程，全部通过，未修改测试键的 ACL。
- 挂起创建核对显示：旧位置安装包进程 RID 为 4096（Low），导出包进程 RID 为 8192（Medium）；两个探测进程都在入口执行前终止。
- 正常导出校验、拒绝 Low 目标目录的校验，以及两个 PowerShell 脚本的语法检查均通过。临时安装记录和下载目录里的测试安装器已清理。
- 本轮没有执行正式客户端的安装或卸载，用户授权与恢复数据目录未被改动。
- `git diff --check` 通过。只有安装模板与说明变更，不需要重新编译 Rust 业务代码。
