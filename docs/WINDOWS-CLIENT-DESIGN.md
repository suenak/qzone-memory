# Windows 优先的客户端界面

拾忆的主要工作是尝试恢复有可读互动线索的已删说说。相册、视频、留言、收藏是独立的资料保存流程，继续保留各自入口和操作含义。

## 统一呈现

- Windows 使用系统窗口标题栏、Segoe UI Variable / Segoe UI 字体、紧凑侧栏和工具栏；蓝色选中轨道表明当前位置。
- 页面名称只在应用工具栏显示，页面内保留说明、操作和可访问的语义标题。
- 概览按本地内容、年份、互动与最近任务组织；说说保留时间轴和卡片模式。
- 控件、边框、面板、密度与主题通过设计令牌及共享组件实现。暖色只用于年份、时间轴等回忆语义。
- 其他桌面平台共享界面，macOS 显示 ⌘ K 搜索快捷键；Windows/Linux 显示 Ctrl K。
- Windows 小窗口使用紧凑导航轨道。手机使用底部导航和「更多」，保留大触控目标；图片预览、筛选和资料页面仍共用同一份功能。
- 恢复入口统一为「恢复任务」，相册等同步不改成说说恢复。没有数据、读取失败、授权不足的提示不伪造进度或数据。

## 验证边界

浏览器验证脚本和测试状态仅放在工作区 output/client-design，不随客户端分发。截图包含明确标注的界面验证内容，并非真实账号数据。

本机缺少 design-cross-platform-ui 子技能，本次使用 orchestrate-frontend-design 与 frontend-design 的指导。跨平台适配通过共用 Vue 页面、CSS 与现有平台判断实现；不把浏览器视口检查当作 Windows/macOS/Linux/Android/iOS 安装包的实机测试。

## 本次检查

- Vue 类型检查与 Vite 构建通过；Rust `cargo check --all-targets` 通过。
- 浏览器验证 13 个路由 × 5 个视口，共 65 个组合：1440×900、1180×760、800×720、390×844、320×740，没有横向溢出或页面脚本异常。
- 10 项交互检查通过：主题、键盘搜索、表单焦点、减少动效、空数据、失败重试入口和手机导航等。
- 5 种平台标识的浏览器模拟检查通过：Windows/macOS/Linux 保留桌面导航，Android/iOS 使用底部导航；macOS 展示 ⌘ K。
- Windows 窗口标题、Android 应用显示名和 iOS CFBundleDisplayName 统一使用拾忆。应用标识和原有数据目录配置不变。
- 未重新打包、推送或部署；各平台的原生系统对话框、触控和安装流程仍需实机验证。
