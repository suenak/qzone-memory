# 恢复数据完整性与读取性能优化

本轮针对恢复后数据被覆盖、误合并，以及大批量记录读取开销。实现位于
`src-tauri/src/archive.rs`，回归用例位于 `src-tauri/src/archive/data_tests.rs`。

## 行为变化

- 同一动态或互动再次读取时，缺失字段、空正文、空数组和空对象不再清掉已保存的信息。有效的新值仍会更新；未知发布时间 `0` 不再替换已知的正数时间，新记录的未知时间仍保留为 `0`。
- 去掉按正文匹配后删除历史动态的逻辑。只有腾讯提供的同一个说说 ID 才能直接归到同一条记录。没有原始 ID 的历史摘要继续单独保存，因此可能看到相似的历史记录；正文相同不足以确认它们是同一次发布。
- 不同评论 ID 的记录即使正文、发送人和秒级时间相同，也分别保留。相同 ID 的重复读取仍可合并。
- 列表、详情、HTML 导出和联系人关联动态共用互动读取函数。每批最多 200 条动态，按账号和说说 ID 成对查询，避免跨账号混入数据。每批一次 SQL，同时读取评论和点赞；保留现有昵称、回复整理和点赞来源优先级。
- 详情查询放入阻塞线程池，避免 SQLite 查询占用异步执行线程。
- 本轮涉及的迁移及互动查询遇到行读取错误时返回错误，不再把错误行悄悄略过。迁移 JSON 解析失败会回滚事务，也不会写入“已完成”标记，修复原始数据后可以重试。
- 重复写入使用预编译语句缓存，新互动只解析一次。数据合并及写入仍位于同一个 SQLite 事务中。

本轮没有调整数据库结构，也没有修改实际账号数据。旧版本已经丢失的字段无法凭空补回；重新读取时，仍需腾讯接口返回相应信息。

## 验证

在 Windows 本机执行：

```powershell
npm run build
cd src-tauri
cargo fmt --check
cargo check
cargo test --lib
cargo test --manifest-path license-core/Cargo.toml
cargo test --lib compare_interaction_query_cost -- --ignored --nocapture
```

客户端 95 项测试通过，授权校验核心 23 项测试通过。性能对比用例默认忽略，已单独运行成功。Windows、Android ARM64 和 ARMv7 的 Rust 编译检查通过；这不等同于实机验收。

内存 SQLite、Debug 构建、1000 条说说 / 20000 条互动、7 次测量的中位数：

| 指标 | 原逐条查询 | 批量查询 |
| --- | ---: | ---: |
| SQL 执行次数 | 2000 | 5 |
| 互动整理耗时 | 6.051 秒 | 70.315 毫秒 |

该结果只比较相同模拟数据的本地互动查询，断言两种方式生成的数据一致，不代表真实账号、移动设备或网络恢复任务的总体提速。测试不使用耗时阈值作为通过条件。

## 保留的边界

没有原始说说 ID 的历史卡片依然是残留摘要，不能据正文断定真实发布次数。本轮保留已有的摘要分组规则，停止其与可见说说之间的猜测合并。

非空数组仍按接口新快照处理；本轮保护的是空、缺失字段，不能宣称所有不完整数组都已自动补齐。遇到损坏数据的迁移会明确失败，需要修复相应原始数据后重试。

未进行真实账号删帖恢复验收；无法据此承诺找回已被腾讯彻底清除的内容。
