# 已删说说未恢复排查

## 当前证据与限制

用户报告 Windows 实测只能找到空间内未删除的说说，目前尚未提供版本、任务结果或具体记录条件。因此下面是确认的代码缺陷与修复，不是对该次实测根因的最终归因，也没有验证任意真实删除说说已恢复。

恢复依赖腾讯仍可返回的历史消息和互动残留。仍可见的说说接口只能同步尚存内容，不证明删除内容恢复成功。点赞或评论是线索条件，不等于腾讯一定保留了正文。

## 修复

1. 可见说说与历史消息此前每次启动都从 offset 0 开始。长任务限流后可能反复重读同一区间。新增按 QQ 账号与来源保存的断点，包括分页位置、历史空尾验证进度和已完成阶段。先保存页面数据，再推进断点；页面重复读取通过已有记录键合并。完整任务完成后清除本轮来源断点，下一轮重新检查新内容；停止、限流和来源失败保留断点。来源断点 24 小时后重新检查，以应对通知列表变化。
2. 历史分页固定采用 10 条小窗口，不假设较大的 count 一定得到同等数量的数据。仍保留空尾验证与请求频率限制；达到安全扫描上限却没有验证空尾时不报告完成。
3. 有些旧记录带有旧昵称，按当前昵称前缀筛选会漏掉。正文标题有明确 QQ 号链接时优先按 QQ 号确认归属并去掉旧昵称。标题明确链接好友账号时，不能因为同名就当成本人。没有可靠账号链接的旧格式仍保留原有昵称校验，不把未知归属的文字塞进本人说说。
4. 来源失败或存在未解决的跳过页时返回 partial，任务页、概览和侧栏显示未读取完整。失败详情默认展开；不会把可见内容保存成功显示成恢复全部完成。历史残留统计使用实际匹配的本人记录数量，不把所有扫描到的卡片当成可恢复记录。
5. 历史响应原始字节先检查 UTF-8；旧 GBK / GB18030 响应使用对应解码，避免中文昵称和正文被替换字符破坏后无法匹配。不识别的编码返回错误，避免当成无记录。
6. 移动互动列表即使返回 hasmore=1，原代码仍会因当前页为空而停止；有下一页却缺少游标、vFeeds 字段缺失也会被默认为正常结束。现在空窗口仍按服务器游标续读，响应不完整则暂停并保留断点，不自动跳过。兼容数字、布尔、数字字符串的 hasmore 标记，未知标记报错；已有重复游标检查继续防止死循环。

源分页参考：[GetQzonehistory 的批次读取](https://github.com/ll0v0ll/GetQzonehistory/blob/main/main.py)。

- 81 项 Rust 测试通过，新增历史断点跨限流窗口保留、已完成可见来源不重启、断点账号隔离与过期，以及旧昵称／同名好友、UTF-8 与 GBK 响应解析测试。另验证空互动窗口保留下一页，以及不完整分页响应不能误报结束。
- 前端类型检查与构建、Windows Rust 检查和 Android x86_64 开发目标编译检查通过。Android 检查不代表 APK 或真机验收。
- 浏览器在 390 与 1440 像素宽度模拟 partial 任务，确认状态与失败详情默认可见、无横向溢出。这是模拟状态，截图不是实际恢复结果。
- 没有删除现有数据库或记录，没有请求任何 QQ 账号密码／Cookie，也没有运行真实账号的全量恢复来证明修复效果。
- 已构建包含本次修复的 Windows x64 验证安装包：`../output/recovery-test-2026-10-13/qzone-memory_1.2.6_x64-recovery-test-setup.exe`（相对仓库根目录）。仍显示 1.2.6，文件名和同目录 manifest 区分这次验证构建；未发布到 GitHub、官网或线上更新清单。安装包构建成功不代表已删说说的真实恢复验收通过。
