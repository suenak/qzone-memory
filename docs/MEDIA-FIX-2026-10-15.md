# 1.2.8 图片与历史消息修复

## 已确认的原因

1. 说说页在 `loading` 仍为真时注册图片观察器。当时实际卡片被骨架屏替代，观察器没有找到节点，之后也没有补注册。表现是一直显示“等待加载”，没有调用原生图片命令。
2. 相册封面只通过前端匿名读取，无法复用原生 QQ 会话和持久图片缓存；旧记录的 HTTP 地址还会被 HTTPS 权限或系统网络策略阻止。
3. 封面重试按钮和卡片点击层处于相同层级，后出现的卡片层拦截点击，看起来能重试，实际点击会打开相册。
4. 历史消息返回的内容是 JavaScript 对象字面量：既有未加引号的字段，也有 `undefined`，HTML 按条目保存在 `data.data` 数组中，数组末尾还有 `undefined` 占位。旧正则无法可靠处理这种响应，也把明确成功的空页当成接口异常。

## 修复

- 说说列表完成渲染后再注册图片观察器，筛选和翻页仍可重新观察。
- 新增原生 `load_library_cover`，按当前账号查询封面，优先使用本地缓存；下载时遵守软件授权与账号检查，QQ Cookie 只在原生侧发送至受信任的 QQ 图片域名。
- 兼容 QQ CDN 的 HTTP、相对协议地址；拒绝带账号信息或使用不安全协议的地址。
- 提高封面重试按钮的局部层级，验证实际鼠标点击能够恢复图片。
- 历史响应按有限的数据语法解析，不执行 JavaScript。支持转义、未加引号的字段、分条 HTML 和 `undefined` 占位。
- 仍拒绝错误状态、无法识别的表达式、不完整的记录及缺少内容的异常响应。只在成功且明确没有记录时接受不带 HTML 的空页。
- Windows 本地修复构建版本更新为 1.2.8；未推送远端、发布安装包或修改线上更新清单。

## 验证

- 用本机 Windows 已保存的登录会话，调用实际原生下载代码，成功取得两张真实图片：132,735 字节、72,939 字节，均识别为有效图片且不是 QQ 占位图。
- 同一会话实际读取到 8 条历史记录，解析出 5 条可还原事件。该结果不代表找回了 5 条已删除说说；本次读取没有写入用户的说说数据库。
- 104 项默认 Rust 测试通过，2 项手动测试默认忽略；其中真实账号诊断另行显式执行通过。
- 前端生产构建通过。Playwright 验证 390 像素下图片在滚动进入视区后自动加载、封面优先调用原生读取且不走匿名请求；1440 像素下封面正常显示，加载失败后的重试按钮可实际点击并恢复图片。
- Android ARM64 和 ARMv7 原生代码检查通过；保留已有的 4 条桌面凭据代码未使用警告。
- 浏览器页面验证使用受控 IPC 与测试图片，不等同于 Android 真机测试。真实网络证据来自上述 Windows 原生诊断。

诊断不会输出 Cookie、登录令牌、签名图片地址或历史正文；图片下载到临时目录后自动清理。没有关闭正在运行的客户端或改写其登录凭据。

Windows 安装包生成后，需退出旧版再安装新版本；源码变更不会自动更新正在运行的 1.2.7。Android 使用相同修复代码，但本次没有连接手机，不声称已在手机安装验证。
